# Overrides локализации для элементов шкалы

Эта система позволяет для конкретной локали менять набор объектов на шкале без изменения общего `items.json`.

## Зачем это нужно

Через overrides можно:

- скрывать нерелевантные для локали общие объекты
- заменять существующие объекты локальными аналогами
- добавлять новые объекты только для конкретного языка или региона
- при необходимости использовать локальные изображения вместо общих

---

## Структура файлов

### Базовые данные

Общий манифест объектов:

```text
public/data/items.json
```

Общие изображения:

```text
public/img/textures/items/{id}.png
```

### Локальные overrides

Для каждой локали рядом хранится отдельный override-файл:

```text
public/data/overrides/{locale}/items.override.json
```

Локальные изображения:

```text
public/img/textures/overrides/{locale}/items/{id}.png
```

Пример:

```text
public/data/overrides/ru/items.override.json
public/img/textures/overrides/ru/items/288.png
public/img/textures/overrides/ru/items/330.png
```

---

## Общая логика работы

При старте приложения данные собираются в таком порядке:

1. Загружается общий `items.json`
2. Определяется текущая локаль
3. Если для локали есть `items.override.json`, он подмешивается поверх общего манифеста
4. Формируется итоговый `resolvedManifest`
5. По итоговому манифесту загружаются текстуры
6. На шкале рендерятся уже итоговые элементы

---

## Формат `items.override.json`

Поддерживаются 4 секции:

- `remove` — удалить общие элементы
- `replace` — заменить существующие элементы
- `add` — добавить новые элементы
- `textures` — указать, для каких id нужно брать локальную картинку

Пример полного файла:

```json
{
  "remove": ["041", "288"],
  "replace": {
    "105": {
      "layout": {
        "x": 0,
        "y": 0,
        "width": 300,
        "height": 180
      },
      "size": {
        "exponent": 2,
        "coeff": 1,
        "realRatio": 1
      },
      "visualLocation": {
        "titleX": 0,
        "titleY": 0,
        "titleScale": 1,
        "titleWrap": true,
        "descriptionX": 60,
        "descriptionY": -120
      }
    }
  },
  "add": {
    "330": {
      "layout": {
        "x": 0,
        "y": 0,
        "width": 260,
        "height": 190
      },
      "size": {
        "exponent": 3,
        "coeff": 1,
        "realRatio": 1
      },
      "visualLocation": {
        "titleX": 0,
        "titleY": 0,
        "titleScale": 1,
        "titleWrap": true,
        "descriptionX": 70,
        "descriptionY": -100
      }
    }
  },
  "textures": {
    "105": true,
    "330": true
  }
}
```

## Удаление элементов

### `remove`

Секция `remove` содержит массив id, которые нужно убрать из общего манифеста для текущей локали.

Пример:

```json
{
  "remove": ["041", "288"]
}
```

Это означает:

- элемент `041` не будет показан в этой локали
- элемент `288` не будет показан в этой локали

### Когда использовать

Используй `remove`, если:

- объект культурно нерелевантен
- объект дублирует более подходящий локальный аналог
- объект не нужен конкретной аудитории

### Важно

Удаление происходит только для текущей локали.
В других локалях объект остается.

---

## Замена элементов

### `replace`

Секция `replace` позволяет заменить существующий объект по его id.

Ключ — id объекта, значение — полный новый объект в формате frame entry из `items.json`.

Пример:

```json
{
  "replace": {
    "288": {
      "layout": {
        "x": 20,
        "y": 10,
        "width": 200,
        "height": 140
      },
      "size": {
        "exponent": -2,
        "coeff": 2.15,
        "realRatio": 1
      },
      "visualLocation": {
        "titleX": 0,
        "titleY": 0,
        "titleScale": 1,
        "titleWrap": true,
        "descriptionX": 60,
        "descriptionY": -100
      }
    }
  }
}
```

### Когда использовать

Используй `replace`, если нужно:

- оставить тот же id, но полностью поменять объект
- заменить общий объект на локальный аналог
- изменить позиционирование, размер, коэффициенты или прочую геометрию
- заменить картинку и данные, не меняя ссылки на id в переводах

### Что именно заменяется

При `replace` заменяется вся запись объекта целиком:

- `layout`
- `size`
- `visualLocation`

Если нужен только локальный текст, лучше менять его через i18n, а не через override-структуру.

---

## Добавление новых элементов

### `add`

Секция `add` позволяет добавить новый объект, которого нет в общем `items.json`.

Ключ — новый id, значение — полный объект.

Пример:

```json
{
  "add": {
    "330": {
      "layout": {
        "x": 0,
        "y": 0,
        "width": 260,
        "height": 190
      },
      "size": {
        "exponent": 1,
        "coeff": 1,
        "realRatio": 1
      },
      "visualLocation": {
        "titleX": 0,
        "titleY": 0,
        "titleScale": 1,
        "titleWrap": true,
        "descriptionX": 80,
        "descriptionY": -100
      }
    }
  }
}
```

### Когда использовать

Используй `add`, если:

- нужен новый локальный объект, отсутствующий в общей версии
- локальная аудитория ожидает увидеть знакомый ей предмет
- замены недостаточно и нужно расширить список объектов

### Важно

В текущей реализации лучше использовать только числовые string-id:

```json
"330"
"331"
"450"
```

Не используй `uuid` или произвольные строковые id, потому что текущий код сортирует и обрабатывает объекты как числа.

---

## Локальные изображения

### `textures`

По умолчанию все изображения грузятся из общей папки:

```text
public/img/textures/items/{id}.png
```

Если для id нужно использовать локальную картинку, это явно указывается в `textures`.

Пример:

```json
{
  "textures": {
    "288": true,
    "330": true
  }
}
```

Это означает:

- для `288` брать изображение из локальной папки
- для `330` брать изображение из локальной папки

Тогда ожидаются файлы:

```text
public/img/textures/overrides/{locale}/items/288.png
public/img/textures/overrides/{locale}/items/330.png
```

### Когда использовать

Используй `textures`, если:

- объект заменен и ему нужна другая картинка
- объект добавлен только для этой локали
- геометрия осталась прежней, но изображение должно быть локальным

### Если `textures` не указан

Если id отсутствует в `textures`, картинка будет браться из общей папки.

---

## Тексты объектов

Тексты объектов не рекомендуется хранить в override-файле.

Лучше оставлять их в системе переводов, где для каждого id есть:

- `title`
- `description`

Пример:

```json
{
  "288": {
    "title": "1 копейка России",
    "description": "1 копейка — одна из самых маленьких и почти исчезнувших из повседневной жизни монет современной России..."
  }
}
```

### Почему так лучше

Это дает более чистое разделение ответственности:

- `items.override.json` отвечает за состав и визуальные данные объектов
- i18n отвечает за тексты

---

## Правила и ограничения

### 1. Используй id в строковом формате

Рекомендуемый формат:

```json
"041"
"288"
"330"
```

Лучше всегда использовать id с `padStart(3, '0')`.

### 2. Не переиспользуй один и тот же id в разных секциях

Нельзя делать так:

```json
{
  "remove": ["288"],
  "replace": {
    "288": { ... }
  }
}
```

Один id должен участвовать только в одном действии.

### 3. Для новых объектов используй новые числовые id

Для `add` используй id, которых нет в базе.

Пример:

- если общий набор заканчивается на `329`
- новые локальные объекты начинаются с `330`

### 4. Ring-элементы не стоит трогать

Если первые системные id зарезервированы под кольца шкалы, их не нужно удалять или заменять через overrides.

## Типовые сценарии

### Удалить объект только для одной локали

```json
{
  "remove": ["041"]
}
```

### Заменить объект локальным аналогом, сохранив тот же id

```json
{
  "replace": {
    "288": { ... }
  },
  "textures": {
    "288": true
  }
}
```

### Добавить новый объект только для одной локали

```json
{
  "add": {
    "330": { ... }
  },
  "textures": {
    "330": true
  }
}
```

---

## Рекомендуемый порядок выбора действия

### Используй `remove`, если

объект нужно просто скрыть.

### Используй `replace`, если

нужно сохранить тот же id, но поменять сам объект.

### Используй `add`, если

нужно ввести новый объект, которого раньше не было.

### Используй `textures`, если

для объекта нужна локальная картинка.

## Кратко

Система overrides позволяет локали:

- убирать ненужные общие объекты через `remove`
- заменять существующие через `replace`
- добавлять новые через `add`
- подставлять локальные изображения через `textures`

Это дает гибкий способ адаптировать шкалу под разные страны и языки без копирования всего `items.json`.
