# Добавление элемента шкалы

Работай из корня проекта. Веди этапы в разговоре, не создавай планы и служебные отчёты. Не меняй код приложения и схемы данных ради добавления объекта. Сохраняй чужие рабочие изменения.

## 1. Уточнить задачу

Прочитай `AGENTS.md` и [docs/add-new-object.md](../../../docs/add-new-object.md). Для локального режима прочитай также [docs/override-objects.md](../../../docs/override-objects.md). Ссылки относительны папке скилла, остальные пути ниже — корню проекта. Сверяй документацию с текущими данными и загрузчиком: примеры могут показывать PNG, но сейчас используются WebP.

Уточни только недостающие сведения: объект и разновидность; режим (общий новый, локальный новый, локальная замена); целевые локали; ID заменяемого объекта. Поддерживаемые локали определяй по `public/locales/*/objects.json`. Не создавай новую локаль автоматически. Для общего объекта переводы нужны на всех языках. Глобальная замена требует отдельного согласования объёма работы.

Попроси пользователя приложить изображения-референсы или готовую картинку. Если готовой картинки нет, предложи генерацию по референсам либо по описанию. Запрос вложений отправляй обычным сообщением: инструменты текстовых вопросов не принимают файлы. Не повторяй уже отвеченные вопросы и не считай молчание выбором режима или разрешением замены.

## 2. Подготовить ID и изображение

Для нового объекта вычисли глобальный `max + 1` по числовым ID из:

- `public/data/items.json` → `frames`;
- всех `public/data/overrides/*/items.override.json`: `remove`, ключи `replace`, `add`, `textures`, `slugs`;
- всех `public/locales/*/objects.json` → `items`;
- имён файлов общих и локальных текстур, включая незакоммиченные.

Используй строку `padStart(3, '0')`, не обрезай более длинные ID. Повторно проверь конфликты перед записью. Для локальной замены сохраняй старый ID и имя текстуры. Проверь наличие базового объекта; не заменяй системные кольца. Если объект существует только в локальном `add`, согласуй обновление этой записи вместо создания дублирующего `replace`. Один ID не должен участвовать одновременно в `remove`, `replace`, `add`.

Просмотри референсы и несколько подходящих текстур проекта. Подготовь одиночный объект в векторном стиле: узнаваемый силуэт, простые формы, без фона, надписей, рамок и лишних полей. Результат — растровый WebP, не SVG. Генерацию и удаление фона выполняй доступным инструментом генерации/редактирования с прозрачным фоном, используя imagegen-скилл, если доступен. Если инструмент недоступен, запроси готовый прозрачный PNG/WebP. Покажи результат пользователю и учти замечания.

Конечные пути:

- Общий: `public/img/textures/items/{id}.webp`.
- Локальный: `public/img/textures/overrides/{lang}/items/{id}.webp` для каждой выбранной локали.

Из корня проекта запусти встроенный конвертер:

```sh
node .agents/skills/add-scale-object/scripts/convert-to-webp.mjs input.png public/img/textures/items/NNN.webp
```

Он принимает PNG/WebP и явный выходной путь, сохраняет пропорции, ограничивает обе стороны 350 px без увеличения маленьких исходников, использует WebP `quality: 80`, `effort: 6`. Исходник сохраняется. `--overwrite` используй только для согласованной замены конкретной текстуры; входной и выходной файлы должны различаться. Если готовое изображение уже в конечном пути, проверь его и при необходимости используй отдельный исходник для конвертации.

Проверь метаданные и изображение визуально: WebP, большая сторона ≤ 350 px, настоящие прозрачные пиксели, отсутствие нарисованной шахматной подложки, целый силуэт без чрезмерных пустых полей. Альфа-канал сам по себе не доказывает прозрачность. 350 px текстуры не определяют физический размер и `layout`.

## 3. Выбрать описание

Название (`title`) должно строго соответствовать названию объекта, указанному пользователем. Не предлагай творческие заголовки, метафоры или альтернативные названия: например, здесь допустимо только «Большой Канарский телескоп». Если название не указано или неоднозначно, уточни его; в переводах используй принятое название того же объекта на соответствующем языке. Варианты ниже относятся только к описанию.

Прочитай подходящие записи `public/locales/ru/objects.json`, выбери один образец и назови его ID и заголовок. Предложи **четыре** русских научпоп-описания сопоставимой длины и тона, с разными акцентами и сравнениями. Проверяй факты по надёжным, предпочтительно первичным источникам; ссылки показывай в разговоре, не вставляй служебные ссылки в JSON. Не переноси фактические ошибки образца.

**Остановись до выбора или редакции описания пользователем.** Не выбирай за него и не записывай варианты в переводы.

## 4. Подтвердить размер

После выбора описания уточни измеряемую величину: длину, высоту, диаметр и т. п. Предложи значение с источником, покажи понятные единицы и `coeff × 10^exponent` метров. Для диапазона предложи репрезентативное значение и объясни выбор; для условных или неизвестных размеров обозначь неопределённость. По умолчанию `realRatio: 1`; не меняй его ради свободного места или скрытого изменения научного размера.

**Дождись явного подтверждения величины и значения.** До этого не записывай frame, override и переводы. Если описание содержит другое число, согласуй исправленный текст. Уже полученное явное подтверждение не запрашивай заново.

## 5. Разместить объект

Прочитай текущие `src/classes/entity.ts`, `src/classes/item.ts`, `src/helpers/calculateScale.ts`, `src/helpers/resolveItemsManifest.ts` и соседние объекты. Для локали анализируй итоговый манифест после `remove` → `replace` → `add`, а не отдельный override.

Ищи свободное место среди объектов близкого размера, включая соседние порядки величины. Контейнеры используют `10^exponent × coeff × realRatio`: приводи границы к общему масштабу, не сравнивай исходные `layout.x/y` объектов разных размеров напрямую. Учитывай центрированный anchor, размеры изображений и подписи. Настройки похожего объекта — отправная точка, не готовые свободные координаты.

Задай полный frame: `size`, `layout`, `visualLocation`. Сохраняй пропорции итоговой текстуры в `layout.width/height`. Настрой подпись, карточку и при необходимости `zoomOffset`. При замене сначала проверь прежнее место. Не двигай соседей без необходимости; если требуется существенная перестановка, покажи конфликт и согласуй её. Для общего объекта учитывай также окружение в существующих локальных overrides.

- Общий новый: `public/data/items.json` → `frames`.
- Локальный новый: `public/data/overrides/{lang}/items.override.json` → `add`.
- Локальная замена базового: полная запись в `replace`, не частичный patch.
- Локальная картинка: `textures[id]: true`.

Сохраняй остальные записи и секции. При необходимости используй `node scripts/sort-frames-items.mjs`, предварительно проверив влияние нормализации на рабочие изменения.

## 6. Добавить переводы и SEO

Переводи только согласованные название и описание, сохраняя факты, числа и единицы. Формат: `items[id]: { title, description }`.

Для общего нового объекта:

1. Добавь русский текст в `public/locales/ru/objects.json`.
2. Заполни `scripts/new-object.translations.json` новым ID для всех языков в формате `{ "<lang>": { "<id>": { "title": "…", "description": "…" } } }`. Если файл содержит чужую незавершённую работу, не затирай её: согласуй использование файла.
3. Запусти `node scripts/distribute-object-translations.mjs`.
4. Сразу запусти `node scripts/sort-object-translations.mjs`.
5. Проверь ключ и текст во всех локалях: распределитель пропускает существующие ID, в том числе заранее добавленный русский.

Для локального нового объекта внеси тексты в выбранные локали и **добавь английскую запись нового ID**, даже если `en` не целевая локаль: SEO-сборка требует английский slug для каждого отображаемого объекта. Это не добавляет объект в общую шкалу. Для не-русской локали русский исходник остаётся в разговоре, без лишней записи в `ru`.

При замене напрямую обнови существующий текст только в целевых локалях: распределитель его не перезапишет. Не меняй английскую запись базового объекта, если `en` не согласована. При изменении смысла объекта актуализируй уникальный локальный `slugs[id]` по текущим соглашениям проекта. Сохраняй порядок ключей и форматирование.

## 7. Проверить и завершить

- Согласованность ID, текстур, frame/override и переводов; отсутствие конфликтов override; конечные координаты и положительный размер; корректные пропорции; системные кольца не затронуты.
- Текстура по пути, выбранному `src/helpers/resolveTextureSources.ts`; английская запись для локального нового объекта.
- `npm run slugs:check` и `npm run build`. Проверь diff, включая генерируемые файлы; не откатывай чужие изменения. Отдельно сообщай о прежних ошибках и блокировках.
- В браузере на нескольких близких уровнях зума: прозрачность, подпись, наложения соседей, область клика, описание, приближение. Локальное изменение проверь в целевой и одной нецелевой локали; общее — в базовой и локали с overrides. Если браузер недоступен, прямо скажи: «Размещение визуально не подтверждено».

## 8. Обновить changelog и выпустить версию

После завершения добавления или замены запиши результат в корневой `CHANGELOG.md`, соблюдая язык и формат существующих записей. Укажи объект и затронутые локали, а также связанные изменения текущей задачи. Не приписывай релизу чужую незавершённую работу.

Выпусти patch-версию, если пользователь не указал другой тип: `npm version patch --no-git-tag-version`. Проверь одинаковую версию в `package.json`, корне `package-lock.json` и `packages[""]` lock-файла; заголовок новой секции changelog должен совпадать с ней. Повышай версию один раз на завершённый набор изменений, а не на каждый объект или повторную проверку. Если версия для этого релиза уже поднята, дополни её changelog без повторного bump. Затем выполни `npm run build` с новой версией.

При последующем коммите выбери `skip` в `scripts/bump-version.js`, который вызывается pre-commit hook, чтобы не поднять версию повторно. Этот шаг оформляет локальную версию; push, публикация и деплой выполняются только по отдельному указанию пользователя.

В финале укажи ID, режим, локали, размер, выпущенную версию, ссылки на изменённые файлы и фактические результаты проверок. Не объявляй непроведённые проверки успешными.
